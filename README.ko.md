# BudsBar

삼성 폰 없이 맥에서 **Galaxy Buds4 Pro** 설정을 바꾸는 macOS 메뉴바 앱입니다.
Swift, SwiftUI(`MenuBarExtra`), IOBluetooth RFCOMM으로 만들었고, UI는 시스템 언어에 따라 영어나 한국어로 나옵니다.

> **비공식 프로젝트입니다.** 삼성전자와 관련이 없고, 삼성이 보증하거나 지원하지 않습니다.
> "Galaxy Buds"는 삼성전자의 상표입니다. 사용에 따른 책임은 사용자에게 있습니다.

## 하는 일

- 배터리(왼쪽, 오른쪽, 케이스), 착용 상태, 충전 여부를 보여 줍니다.
- 아래 표의 설정을 바꾸고, 버즈가 변경 때마다 보내는 상태 메시지를 해석해 패널을 맞춥니다.
  (BudsBar에서 바꾼 경우는 확인했습니다. 터치나 폰에서 바꾼 경우도 같은 메시지로 오지만 직접 해 보지는 않았습니다.)
- 로그인 시 자동 실행되고 평소엔 조용히 있습니다. 버즈가 연결돼 있지 않으면 RFCOMM 채널을 닫고, 타이머나
  폴링 없이 IOBluetooth 연결/해제 알림만 기다립니다.
- 메뉴바 아이콘은 항상 보입니다. BudsBar가 버즈와 연결돼 있지 않을 때는 흐리게 표시되고, 패널에는 상태와
  **맥으로 가져오기** 버튼만 나옵니다.
- 폰에서 버즈를 스스로 뺏어 오지 않습니다. 버즈가 알아서 맥에 붙으면 설정 채널을 열고, 자동 재연결은 버즈를
  page(호출)하지 않습니다. page는 **맥으로 가져오기**를 눌렀을 때만 합니다. 버즈를 호출한 뒤 연결이 3초 동안
  유지되는지 확인하고(폰을 우선하는 버즈는 1초 안에 끊는 일이 많습니다) 설정 채널을 엽니다. 끊기면 2초 간격으로
  최대 4번까지 다시 시도하며 "가져오는 중 2/4"처럼 진행 상황을 보여 줍니다. 버튼을 다시 누르면 취소됩니다.
  재시도는 그 한 번 누른 동작 안에서만 돕니다.
- 디버깅용 CLI(`BudsBar --cli …`)가 있어 raw 프레임 송신과 수신 hex 덤프를 할 수 있습니다.

## 기능별 상태

macOS 26, Apple Silicon에서 Galaxy Buds4 Pro 한 대(SM-R640, 펌웨어 R640XXU0AZD2, 상태 리비전 4)로 테스트했습니다.

- **검증됨**: 버즈가 명령에 ACK했고, 버즈가 돌려보내는 상태 메시지에서도 바뀐 값이 확인됨
- **ACK만**: 버즈가 ACK는 했지만 상태 메시지에 반영되지 않아 실제 효과는 확인하지 못함
- **미검증**: 구현은 했지만 일부러 시험하지 않음
- **사용 불가**: UI에서 비활성으로 두고 이유를 표시

같은 코드를 쓰지만, 손으로 하나씩 눌러 보지는 않았습니다.

### 맥에서는 안 되는 기능

삼성 폰에서 돌아가거나 삼성 폰이 있어야 하는 기능이라 BudsBar로는 제공할 수 없습니다.
360 오디오와 헤드 트래킹, UHQ(24비트) 오디오와 삼성 심리스 코덱, 실시간 통역, 펌웨어 업데이트, SmartThings Find, 빅스비 자체.

또한 BudsBar는 공장 초기화, 재부팅과 전원 끄기, 펌웨어 업데이트(FOTA), 테스트 모드, 페어링 모드 명령을
절대 보내지 않습니다. 이 메시지 ID들은 전송 계층에서 막혀 있어 `--cli raw`로도 보낼 수 없습니다.

## 빌드와 설치

macOS 14 이상과 Swift 6(Xcode 커맨드라인 도구)이 필요합니다. Apple Silicon에서 테스트했습니다.

```sh
git clone https://github.com/PROVE1352/BudsBar.git
cd BudsBar
./build.sh
```

`build.sh`는 릴리스 바이너리를 빌드해 `BudsBar.app`으로 묶고(`LSUIElement`, `NSBluetoothAlwaysUsageDescription` 포함)
ad hoc 서명한 뒤 `~/Applications/BudsBar.app`에 설치합니다. 처음 열면 macOS가 블루투스 권한을 묻습니다.
ad hoc 서명이라 다시 빌드하면 권한을 또 물을 수 있습니다. 첫 실행 때 로그인 항목으로 등록되며,
패널의 기타 → 로그인 시 실행에서 끌 수 있습니다.

메뉴바 아이콘은 항상 있고, 버즈가 BudsBar와 연결돼 있지 않으면 흐리게 보입니다.
특정 버즈만 쓰려면 `defaults write io.github.prove1352.BudsBar deviceAddress xx-xx-xx-xx-xx-xx`.

## CLI

번들 안의 바이너리를 실행합니다. RFCOMM 채널은 한 프로세스만 잡을 수 있으니 메뉴바 앱을 먼저 종료하세요.

```sh
B=~/Applications/BudsBar.app/Contents/MacOS/BudsBar
$B --cli status           # 해석한 상태 + 펌웨어
$B --cli -v nc adaptive   # 노이즈 컨트롤 변경, 모든 프레임 출력
$B --cli raw 78 01        # msgId + payload 송신 후 응답 출력
$B --cli dump 30          # 30초 동안 받은 프레임 hex 덤프
$B --cli esu              # 상태 payload를 오프셋과 함께 출력
$B --cli bring            # 맥으로 가져오기, 진행 상황 출력 (폰에서 버즈를 가져옴)
$B --cli selftest         # 오프라인 프레임/CRC 테스트 벡터
$B --cli help             # 전체 명령
```

## 프로토콜 메모

프레임은 삼성 SPP 서비스 `2e73a4ad-332d-41fc-90e2-16bef06523f2` 위에서
`FD [size|flags LE] [msgId] payload [CRC16-XMODEM LE] DD` 형식입니다. Buds4 Pro에서 GalaxyBudsClient 디코더와 다른 점:

- 확장 상태(`0x61`, 62바이트): 주변소리 음색은 오프셋 36(31 아님), 선명한 통화음은 44(43 아님),
  자동 일시정지는 46(45 아님), 사이렌 감지는 52.
- 노이즈 컨트롤 전환 순서(`0x79 [L][R]`, 상태 오프셋 21 = `L<<4 | R`): bit0 주변소리, bit1 적응형, bit2 끄기, bit3 ANC.
  ACK는 3바이트(`79 L R`).
- `LOCK_TOUCHPAD`는 8바이트. 터치 허용 비트는 상태 오프셋 10(bit0 길게, 1 세 번, 2 두 번, 3 한 번,
  4 통화 중 두 번, 5 통화 중 길게, 6 스와이프).
- 헤더 상위 비트는 프레임마다 바뀌어(순번처럼 보임) "타입" 비트로 쓸 수 없습니다. BudsBar는 하위 10비트(size)만 씁니다.
- 펌웨어 문자열은 요청하지 않아도 `0x68`로 옵니다(왼쪽/오른쪽 각 20바이트).
